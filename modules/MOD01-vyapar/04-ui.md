## Design System Foundation (read once; every UI item references these by name)

### F1. Platform and head-of-document rules (mobile-first web)

- **Targets:** Chrome on Android first, Safari on iOS second, desktop browsers as the responsive fallback. No native-only components anywhere; every "sheet", "push", "toast" and "nav bar" below is HTML + CSS transforms.
- **`<head>` (every page of the Vyapar web client):**
  - `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` — `viewport-fit=cover` is required for `env(safe-area-inset-*)` to be non-zero on iOS (MDN `env()`, opened).
  - `<meta name="color-scheme" content="light dark">` plus `:root { color-scheme: light dark; }` so native form controls, scrollbars and the browser's own UI follow the active scheme (web.dev "color-scheme", opened; MDN `prefers-color-scheme`, opened).
  - `<meta name="theme-color" content="#F7F4EE" media="(prefers-color-scheme: light)">` and `<meta name="theme-color" content="#0B1226" media="(prefers-color-scheme: dark)">` — tints Chrome Android's address bar to the surface colour (MDN `theme-color`, opened: supported on Chrome Android, limited elsewhere — treated as progressive enhancement).
  - Web app manifest: `name` "Vyapar by ForKhatri", `short_name` "Vyapar", `start_url` "/discover", `display` "standalone", `background_color` `#F7F4EE`, `theme_color` `#0B1226`, icons 192 px and 512 px (plus a maskable 512 px), `prefer_related_applications` absent — the Chrome installability list from web.dev "install-criteria" (opened: HTTPS, name/short_name, 192 + 512 icons, start_url, display standalone/fullscreen/minimal-ui/window-controls-overlay, `prefer_related_applications` not true, user engagement ≥ 30 s + one tap). The install prompt (`beforeinstallprompt`) is deferred and only surfaced after a first success moment (UX03 platform rule 1: UX04 Result / UX10 Published / UX12 Sent), never on the UI01 return-landing state (and never on the platform's sign-in screens, which Vyapar does not render).
  - Font preloads: `<link rel="preload" as="font" type="font/woff2" crossorigin>` for the Latin 400 and 600 Noto Sans files only; Devanagari/Telugu files load on demand via `unicode-range` (F3).
- **Viewport height:** full-height screens use `min-height: 100svh` (stable small viewport) and the sticky footers use `position: sticky; bottom: 0`, never `100dvh` for the page frame — MDN `length` (opened) warns dynamic units resize content during scroll on mobile browsers.
- **Safe area:** bottom nav and sticky footers get `padding-bottom: calc(var(--fk-space-2) + env(safe-area-inset-bottom, 0px))`; the app bar gets `padding-top: env(safe-area-inset-top, 0px)` in standalone (installed) mode.
- **Pull-to-refresh and scroll chaining:** `html { overscroll-behavior-y: none }` globally (MDN `overscroll-behavior`, opened — `contain`/`none` disables the browser's native pull-to-refresh so the app's own pull-to-refresh, present only on Discover/Businesses/Results/Activity per UX cross-flow rule (g), is the single refresh gesture); every bottom sheet's scroll container uses `overscroll-behavior-y: contain` so reaching its end never scrolls the page behind it.
- **Back:** every sheet, modal and pushed screen is a history entry (`history.pushState`), so the hardware/browser Back pops it exactly like the header back arrow (UX cross-flow rule 8).

### F3. Typography (Latin + Devanagari + Telugu as one system)

- **Families:** `Noto Sans` (Latin), `Noto Sans Devanagari`, `Noto Sans Telugu` — all three confirmed available from the Google Fonts CSS API at weights 400/500/600/700 with `font-display: swap` (API response opened: `family=Noto+Sans+Devanagari:wght@400..700&family=Noto+Sans+Telugu:wght@400..700&family=Noto+Sans:wght@400..700&display=swap`); Noto is SIL OFL-licensed and covers Devanagari and Telugu as harmonised families (notofonts.github.io, opened). Self-host as `woff2` subsets (the API served `.ttf` to a non-browser UA; browsers receive woff2) with `unicode-range` so a Hindi member does not download Telugu glyphs.
- **`@font-face`:** four weights per family, `font-display: swap` (MDN `font-display`, opened: "extremely small" block period, infinite swap — text is never invisible on a 3G connection; the reflow when Noto arrives is accepted and minimised by matching fallback metrics with `size-adjust` where supported).
- **Stacks:** `--fk-font: "Noto Sans", "Noto Sans Devanagari", "Noto Sans Telugu", system-ui, -apple-system, "Segoe UI", Roboto, "Nirmala UI", "Gautami", "Mangal", sans-serif;` and script-first overrides `:lang(hi) { font-family: "Noto Sans Devanagari", "Noto Sans", "Nirmala UI", "Mangal", sans-serif }` · `:lang(te) { font-family: "Noto Sans Telugu", "Noto Sans", "Nirmala UI", "Gautami", sans-serif }` — member-authored content carries its own `lang` attribute (FR42 language tag), so a Hindi listing inside a Telugu UI still renders in the right face.
- **Scale (rem, root 16 px; UX rule: minimum body 16 px, no all-caps, body line-height ≥ 1.6):**

| Token | Size | Line-height (Latin) | Line-height `:lang(hi)`, `:lang(te)` | Weight | Use |
|---|---|---|---|---|---|
| `--fk-type-display` | 1.75rem (28) | 1.3 | 1.5 | 700 | Return-landing wordmark / language-pick title (UI01), Result "Your listing is live", full-screen states |
| `--fk-type-title-lg` | 1.375rem (22) | 1.35 | 1.55 | 600 | Screen titles (app bar), detail H1 |
| `--fk-type-title` | 1.125rem (18) | 1.4 | 1.6 | 600 | Card titles, section headers, sheet titles |
| `--fk-type-body` | 1rem (16) | 1.6 | 1.75 | 400/500 | Body, inputs, buttons, chips, nav labels (≥ 360 px) |
| `--fk-type-body-sm` | 0.875rem (14) | 1.6 | 1.75 | 400/500 | Trust/paid labels, meta lines, helper text, nav labels (< 360 px) |
| `--fk-type-caption` | 0.8125rem (13) | 1.5 | 1.7 | 400 | Timestamps, counters, "Last checked" — never for a label a member must trust (price, verification, Sponsored) |

  Devanagari and Telugu get the taller line boxes because Google Fonts' own metrics guide (opened) says Devanagari's "very tall and shallow glyphs" need vertical metrics exceeding the Latin 120–130% norm to avoid interline collisions, and Indic conjunct stacks resist clipping-safe alignment. Nothing is set in uppercase (`text-transform: none` everywhere — Devanagari/Telugu have no case and the UX rule bans all-caps). Numerals stay Latin digits in identifiers (GSTIN, PAN, phone) and follow locale in dates/amounts (`Intl.NumberFormat`, `Intl.DateTimeFormat`).

### F4. Spacing, shape, elevation, layout grid

- **Spacing:** 4 px base — `--fk-space-1 0.25rem` · `-2 0.5rem` · `-3 0.75rem` · `-4 1rem` · `-5 1.5rem` · `-6 2rem` · `-7 3rem`. Screen gutter 1rem (phones), 1.5rem (≥ 600 px). Vertical rhythm inside cards 0.5rem between lines, 0.75rem between blocks.
- **Radius:** `--fk-radius-sm 0.5rem` (chips, labels, inputs) · `--fk-radius-md 0.75rem` (buttons) · `--fk-radius-lg 1rem` (cards, category tiles) · `--fk-radius-xl 1.5rem` (bottom-sheet top corners, compose-modal top on desktop) · `--fk-radius-full 999px` (nav pill, toggles). Same 16/24 card/sheet radii MOD02 uses.
- **Elevation:** light — `--fk-shadow-1: 0 1px 2px rgb(16 26 51 / 0.06), 0 1px 3px rgb(16 26 51 / 0.10)` (cards), `--fk-shadow-3: 0 -4px 24px rgb(16 26 51 / 0.16)` (bottom sheets/toasts), bottom nav uses a top border only. Dark — no shadows; raised surface + `--fk-border-subtle`.
- **Breakpoints (mobile-first, min-width):** `--fk-bp-compact` < 360 px (nav label steps to `body-sm`, 3-state controls stack) · `--fk-bp-phone` 360–599 (1 column, full-width buttons) · `--fk-bp-wide` ≥ 600 (2-column result lists, 4-column category grid, buttons still full-width inside a 480 px max form) · `--fk-bp-desktop` ≥ 900 (bottom nav becomes a 240 px left rail with the same five items and labels; sheets become centred `<dialog>`s max 480 px wide; content column max 720 px; pushed detail screens render in the same column) · `--fk-bp-console` ≥ 1024 (Admin Console list + right detail pane).
- **Container:** `.fk-page { max-width: 45rem; margin-inline: auto; padding-inline: var(--fk-space-4) }`.

### F5. Iconography and cultural motif

- **Icons:** Material Symbols Rounded (Apache 2.0), variable font subset, `FILL 0` by default and `FILL 1` for the active bottom-nav item and the filled Save bookmark; optical size 24, weight 400; rounded terminals match the shape language. Icons always sit beside text (no icon-only trust/paid meaning — FR43 "no information by colour alone"; UX cross-flow rule). Icon-only *buttons* (Save, Share, Close, Back, overflow) carry `aria-label`s and are 48×48 CSS px hit areas around a 24 px glyph. Excluded from the subset on purpose: `star`, `star_rate`, `grade`, `workspace_premium`, `verified` (the generic blue tick) — so no screen can ever ship a star rating or a generic "Verified" badge.
- **Cultural motif ("jaali" lattice):** a single abstracted geometric lattice derived from a jaali screen — 8-point star-and-cross tiling, 1 px lines, `--fk-navy` at 6 % opacity on light / `--fk-accent` at 8 % on dark — used only (a) behind the wordmark on Vyapar's return-landing state (UI01 — the platform's sign-in screens are not Vyapar's to decorate), (b) as the empty-state illustration frame, (c) as the Result/Published check-mark backdrop. Nowhere else, so it stays a "subtle cultural/geometric influence" (Brand Foundation §12) and never tips into the "traditional community-organization aesthetic" the same section rejects. The same motif family MOD02 chose (jali/kolam), so the platform reads as one brand.
- **Imagery:** V1 has no member photos on listings (no avatar upload FR); identity blocks use a 40 px navy-on-off-white initial monogram tile (`--fk-radius-md`). Category tiles use icons, not photos.

### F7. Motion tokens and implementation vocabulary

Durations and easings are the Material 3 system motion tokens, taken from the material-web repository file `tokens/versions/v0_192/_md-sys-motion.scss` (opened): easings `standard cubic-bezier(0.2,0,0,1)`, `standard-accelerate (0.3,0,1,1)`, `standard-decelerate (0,0,0,1)`, `emphasized-decelerate (0.05,0.7,0.1,1)`, `emphasized-accelerate (0.3,0,0.8,0.15)`; durations short1–4 = 50/100/150/200 ms, medium1–4 = 250/300/350/400 ms, long1–4 = 450–600 ms.

| Token | Value | UX vocabulary it implements |
|---|---|---|
| `--fk-ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | crossfades, chip/pill moves, colour changes |
| `--fk-ease-enter` | `cubic-bezier(0.05, 0.7, 0.1, 1)` (emphasized-decelerate) | anything entering: push in, sheet up, banner down, toast up |
| `--fk-ease-exit` | `cubic-bezier(0.3, 0, 0.8, 0.15)` (emphasized-accelerate) | anything leaving: pop, sheet down, toast away |
| `--fk-dur-press` | 100 ms | chip/button press scale (UX02) |
| `--fk-dur-fade` | 150 ms | tab crossfade (UX03), Save icon fill (UX07), new message fade (UX12), "Changed" chip slide (UX06) |
| `--fk-dur-quick` | 200 ms | return-landing → Discover/first-run fade (UX01), banners, card collapse (UX08/UX11), group collapse (UX11), in-sheet step slide (UX15), contact-card reveal (UX17) |
| `--fk-dur-sheet` | 250 ms up / 200 ms down | modal bottom sheet (UX03) and compose modal (UX04) |
| `--fk-dur-push` | 300 ms in (translateX 100 % → 0, exiting screen translateX 0 → −25 % at 60 % opacity) / 250 ms pop | list → detail push (UX cross-flow b) |
| `--fk-dur-success` | 400 ms | in-button check-mark stroke draw (UX cross-flow f) |
| `--fk-dur-skeleton` | 1600 ms loop | skeleton pulse |

- **Implementation:** pushes and the shared-element title (UX06/UX08/UX09) use the View Transitions API — `document.startViewTransition()` with `view-transition-name: listing-title` on the card title and the detail H1, customised via `::view-transition-old/new` (MDN View Transition API, opened; Baseline across Chrome, Safari and Firefox). Where the API is unavailable the fallback is a CSS `transform` transition on the incoming route with no shared element. Sheets animate `transform: translateY(100%) → 0` on the `<dialog>` and `opacity` on `::backdrop`. Everything animates only `transform` and `opacity` (compositor-only) — never `height`/`top` — except the two "collapse" cases (card hide, group collapse) which animate `grid-template-rows: 1fr → 0fr` for 200 ms.
- **Reduced motion:** `@media (prefers-reduced-motion: reduce)` (MDN, opened; triggered by Android "Remove animations", iOS "Reduce Motion", Windows "Animation effects") sets every duration token to 100 ms, replaces every translate with an opacity fade, disables the skeleton pulse and the indeterminate sweep, renders the success check-mark as a static icon, and turns the shared-element transition off — exactly UX cross-flow rule (h).
- **Deliberate no-motion list:** language chip swap (UX01), progress "2 of 5" text (UX02), Sponsored slot (UX08), filter results re-render other than the "Changed" chip, verification label changes, price/disclosure rows (UX20 — no timers, no pulses), all Admin Console tables (UX19/UX23). Motion is spent only where it explains a spatial relationship (push/pop, sheet), confirms an action (press, check, Save fill), or shows something leaving (collapse with Undo).

### F8. Accessibility baseline applied by every item (FR43, WCAG 2.2 AA)

- Text ≥ 4.5:1 and UI/graphics ≥ 3:1 per F2 (SC 1.4.3, 1.4.11, opened). Every tap target ≥ 48×48 CSS px with ≥ 8 px gaps — twice SC 2.5.8's 24 px minimum (opened). Focus ring per F2 `--fk-focus`: 2 px outer + 1 px inner, `outline-offset: 2px`, ≥ 3:1 change (meets SC 2.4.13 AAA's 2 px-perimeter/3:1 shape even though only 2.4.7 AA is required — opened). Focus is never fully hidden by sticky bars: `scroll-padding-block: 4rem 6rem` on the scroll container so focused items scroll clear of the app bar and sticky footer (SC 2.4.11 Focus Not Obscured, opened). Text resizes to 200 % (SC 1.4.4, opened): no fixed-height rows; all sizes in rem; labels wrap. `:focus-visible` only (no ring on pointer taps). Pointer-cancellable actions (SC 2.5.2) — swipes reveal, never execute.
