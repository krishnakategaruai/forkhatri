# FR part c: members dashboard, shared integrations, deployment

Index: `02-functional-requirements.md`.

## Members dashboard ("ForKhatri in numbers")
Screen SCR-INSIGHTS: route `/insights` (`app/insights/page.tsx`), components `insights/Insights.tsx`, `charts.tsx`, `MemberMap.tsx`; strings `lib/insights-i18n.ts`. Backend: `app/components/insights/` (`interface.py`, `places.py`, `data/`), script `scripts/build_insight_places.py`.

### FR-050 Aggregate statistics open to every member (BR-16) - built
Any signed-in member opens `GET /v1/insights`: total members, growth, where members live (India and world maps), women and men, age bands, and module use. Mangalya candidate figures and Milavn members are fetched from the module APIs (`MODULE_API_URLS`, timeout `INSIGHTS_TIMEOUT_SECONDS` 5 s). Owner decision 2026-09-27: open to all, linked from the hub. Endpoint: API-GET-v1-insights. Tables read: `TBL-identity.member`, `TBL-registry.member_module_entry`. Totals only; no name or contact leaves the endpoint.
Alternate flow: a module that is unreachable is shown as "not reachable" while the page still renders; critique C9 notes this reads as "0 women, 0 men" in dev.
Known gaps (critique C9): no suppression of small cells (under 10), matrimonial fields (marital status, "looking for") appear outside Mangalya, dev counts include QA accounts so must not be quoted in a pitch.

### FR-051 Place resolution - built
City names resolve to coordinates through a built places dataset (`insights/places.py`, generated by `build_insight_places.py`); unknown cities count as "no known city" (shown as a percentage).

## Shared integrations library
Location `shared/forkhatri-integrations` (`forkhatri_integrations`: `payments/`, `messaging/`, `delivery/`, `places/` with `nominatim.py`, `_common.py`); tests in `shared/forkhatri-integrations/tests`; owner decision 2026-10-01 (vendors chosen later; backlog in `BACKLOG.md`).

### FR-052 Payments interface (BR-20) - partial
Typed contract (`payments/types.py`) and adapters (`payments/adapters.py`) including a sandbox; modules select with configuration (`shared:<vendor>` or `shared:payment_services` for MOD06). No real vendor adapter exists. Payments run on a sandbox until a vendor is chosen.

### FR-053 Messaging interface (BR-20, BR-21) - partial
Types for SMS, WhatsApp, email, push (`messaging/types.py`). The platform sign-in uses its own delivery (`app/components/identity/delivery.py`: console, disabled, resend email; `shared` selects `SHARED_SMS_SENDER` or `SHARED_EMAIL_SENDER`). No real SMS or WhatsApp sender; DLT template id setting `SMS_DLT_TEMPLATE_ID` exists.

### FR-054 Delivery interface (BR-20) - partial
Outbox store contract for deliveries (`delivery/__init__.py`); Counsel uses it, Milavn does not yet (BACKLOG B4).

### FR-055 Places lookup (BR-20) - built
Nominatim adapter for geocoding with typed results (`places/`).

## Deployment and operations (BR-22)
Kit: `deploy/` (`docker-compose.yml`, `docker-compose.local-test.yml`, `Caddyfile`, `README.md`, `migrate/`, `scripts/`, `secrets/`).

### FR-056 Edge routing - built (kit), not verified on a real VM
Caddy path routing: `/` entrance; `/mangaly/*`, `/milavn/*` module webs; `/api/identity/*`, `/api/mangaly/*`, `/api/milavn/*` services with prefix stripped; `/internal/*`, `/api/identity/internal*`, `/api/*/docs` return 404. Cloudflare Tunnel is the only ingress.

### FR-057 Migrations and seeds - built
`deploy/migrate/migrate.py` applies `platform/identity-service/db/migrations/001..007` (`--seed-dev` runs `seed_dev_governance.py` and member seeds). Migration list: 001 initial, 002 module registry, 003 basic identity only, 004 dev auth method, 005 governance, 006 Mangalya display name, 007 Marathi and Kannada.

### FR-058 Secrets generation, deploy, backup, restore, rollback, heartbeat - built (scripts)
`generate-secrets.sh` (never prints values), `deploy.sh`, `remote-release.sh`, `server-bootstrap.sh`, `compose.sh`, `backup.sh` (nightly `pg_dump`, optional R2), `restore.sh`, `rollback.sh`, `heartbeat.sh`. Critique C11: stated availability and recovery targets exceed the setup; off-site backup is optional; kit never run end to end on the real VM. Verify by running `deploy/README.md` steps on the VM.

### FR-059 Production guard - built
`Settings._production_guard` refuses start in production if secrets are defaults, `console` delivery is selected, or dev tools are enabled.

### FR-060 Observability - partial
`/health`, request middleware in `main.py` (request id and timing; details unverified), audit log. No metrics dashboard or alerting for the platform (BR-22 gap).
