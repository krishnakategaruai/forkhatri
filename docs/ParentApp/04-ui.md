## Visual direction

Dark-first luminous palette with an adaptive light mode; layered translucent
surfaces with soft depth; an ambient animated background; spring-based motion and
View Transitions between sign-in steps and into sheets; variable typography that
works for English, Hindi and Telugu. The earlier navy/saffron static-shell
direction belongs to the superseded prototype in `web/parent-app/`. Each module
portal takes its accent colour from `registry.module.accent`.

## Page structure

Signed out:

1. ForKhatri wordmark and language choice.
2. One conversational card asking one question at a time: phone or email → 6-digit code (with resend countdown) → name and language for a new member.
3. Secondary link "Use a password instead".
4. When `return_to` points at a module, a line naming it ("Sign in to continue to Milavn").

Signed in:

1. Header: wordmark on the left; notifications bell immediately left of the member avatar; avatar always right-most. No tab bar.
2. Intent bar that shows how it understood the request before opening a module.
3. Module portals, ordered by recent entry, then registry order; availability label on each.
4. Floating command orb for navigation and actions.
5. Account sheet (from the avatar): display name, language, masked phone/email, sign-out, and a quiet note that module profiles are managed inside each module.

## Component rules

- Module portals are reusable and data-driven from `GET /v1/modules`.
- Available, in-development and planned states use different labels and actions; availability is never conveyed by colour alone.
- Buttons have visible focus and clear accessible names.
- Icons supplement labels and never replace essential text.
- The shell remains ForKhatri-branded; module accents never replace the brand.
- No portal says or implies "create a new account".
- Code inputs use `inputmode="numeric"` and `autocomplete="one-time-code"`.
- Errors are shown from stable error codes in the member's language.

## Responsive and motion rules

- Mobile-first; usable at 320 CSS pixels without horizontal scrolling.
- Large tap targets for the code input, orb and portals.
- `prefers-reduced-motion` removes non-essential motion and View Transitions.
- Offline or identity-service-unavailable states use the same visual language, with cached portals shown dimmed.
